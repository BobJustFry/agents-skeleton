# Каркас — готовая AI-команда для любого проекта

**Версия 0.1.18** · номер сборки = число коммитов (файл `VERSION`)

Каркас ставится в папку проекта. После этого Claude Code в этой папке работает как **Chief Orchestrator**: он понимает задачу, планирует, раздаёт работу 22 специалистам, проверяет результат и отчитывается вам.

Подходит для:
- сайтов;
- AI-контента, видео и музыки;
- продвижения;
- веб-, мобильных и десктоп-приложений;
- ботов и AI-продуктов.

Работает как в новых, так и в уже существующих проектах.

## Установка одной фразой

Откройте нужный проект в Claude Code и напишите:

> Установи каркас: https://github.com/BobJustFry/agents-skeleton

Claude сам скачает каркас, проанализирует проект, покажет план и после вашего «да» установит команду. Затем откройте **новую** сессию в этой папке и напишите «Проведи онбординг Каркаса».

### Инструкция для Claude Code (выполняй по шагам, общайся с владельцем по-русски)

1. **Где каркас.** Если `P:\Projects\Каркас` или `%USERPROFILE%\.claude\karkas` уже содержат этот репозиторий (`git remote get-url origin`), обнови его командой `git pull --ff-only`. Иначе склонируй в `%USERPROFILE%\.claude\karkas`. Не клонируй каркас внутрь проекта.
2. **Проект** — текущая папка сессии. Если ты в worktree (`.claude\worktrees\…`), целевой проект — основная папка репозитория (`git rev-parse --show-toplevel` от основной ветки). Уточни у владельца, если сомневаешься.
3. **Git.** Выполни `git status --porcelain`. Если есть незакоммиченные изменения, покажи их владельцу и спроси, закоммитить ли их, с предложенным сообщением. Без его «да» не коммить и не продолжай.
4. **Анализ.** Запусти:
   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File "<каркас>\install.ps1" -Target "<проект>" -Analyze
   ```
   Перескажи владельцу план по-русски и кратко:
   - что добавится;
   - что дополнится: `CLAUDE.md`, настройки, `.gitignore`;
   - конфликты;
   - собственные агенты, хуки и правила проекта.

   Спроси: «Устанавливаю?».
5. **Установка** только после «да»:
   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File "<каркас>\install.ps1" -Target "<проект>" -Yes
   ```
   Потом прочитай `.claude\team\install-report.md` и перескажи его владельцу.
6. **Не коммить установку сам.** Предложи владельцу закоммитить её.
7. **Скажи владельцу:** в текущей сессии новые агенты и хуки не загружены. Нужно открыть новую сессию в этой папке и написать «Проведи онбординг Каркаса».
8. **Обновление** («обнови каркас»): шаги 1, 3 и 4, затем запуск с `-Update -Yes`.

## Как пользоваться

**1. Скачать каркас** (один раз):

```powershell
git clone https://github.com/BobJustFry/agents-skeleton.git P:\Projects\Каркас
```

**2. Новый проект.** Запустите `install.cmd` двойным щелчком, введите путь к новой папке (например `P:\Projects\МойСайт`) и подтвердите план. Папка будет создана вместе с командой.

**3. Существующий проект** — установка идёт в три шага: анализ, установка, онбординг.

1. **Закоммитьте текущие изменения проекта.** Установщик откажется работать, если в git есть незакоммиченные изменения. Так любую установку можно откатить одной командой git.
2. **Посмотрите план** (ничего не меняется):
   ```powershell
   P:\Projects\Каркас\install.cmd "P:\Projects\МойПроект" -Analyze
   ```
   План покажет, что добавится, что объединится и где конфликты.
3. **Установите:** запустите без `-Analyze` и ответьте «да». Что делает установщик:
   - ваши файлы не удаляются и не перезаписываются;
   - если у вас есть свой агент с тем же именем, он остаётся, а версия каркаса кладётся в `.claude\team\incoming\`;
   - `CLAUDE.md` (в корне или в `.claude\`), `.claude\settings.json` и `.gitignore` только дополняются. Их копии сохраняются в `.claude\team\backup\`;
   - отчёт об установке пишется в `.claude\team\install-report.md`.
4. **Онбординг:** откройте проект в Claude Code и напишите **«Проведи онбординг Каркаса»**. Координатор:
   - изучит проект и запишет текущее состояние тестов;
   - сверит правила проекта с правилами каркаса;
   - предложит, как объединить конфликты.

   Код проекта при онбординге не меняется, а спорные решения принимаете вы.

**Откат сразу после установки, пока вы ничего не меняли:** `git checkout -- .` и `git clean -fd .claude docs` вернут проект к состоянию до установки. Перед установкой проект должен быть закоммичен, поэтому эти команды удалят только файлы каркаса. Без git восстановите файлы из `.claude\team\backup\`.

**4. Обновить команду** после изменений в каркасе:

```powershell
P:\Projects\Каркас\install.cmd "P:\Projects\МойПроект" -Update
```

Обновляются только файлы, которые поставил каркас и которые вы не меняли. Если вы правили файл каркаса, ваша версия остаётся, а новая версия ложится в `.claude\team\incoming\`.

## Правила команды

- **Язык.** Между собой и с координатором агенты общаются на английском: это родной язык моделей Claude, на нём они работают точнее. С вами координатор общается только по-русски, и всё, что предназначено вам, пишется по-русски.
- **Свежие данные.** Перед задачей каждый специалист сверяется с официальной документацией. Сведения хранятся в `docs/knowledge/` проекта и обновляются, если им больше 7 дней.
- **Кратко, без воды.** Все отвечают по делу.
- **Если чего-то не знаем:** сначала официальная документация, потом практический опыт из интернета, и только потом вопрос вам.
- **Деньги** тратятся только в рамках бюджета, который вы утвердили на задачу целиком или на этап.
- **С вами спорят.** Если вы ошибаетесь, ни координатор, ни агенты не соглашаются. Спорное решение выполняется, только если вы подтвердили риски своим кодовым словом. Слово хранится только в ваших личных настройках `~/.claude/CLAUDE.md`, в каркасе его нет.
- **Обновления приходят сами.** При старте сессии и при ваших сообщениях проект молча, не чаще раза в 15 минут, сверяет свою версию с GitHub. Если вышла новая версия, координатор один раз предложит обновиться. Обновление — только после вашего «да», ваши правки сохраняются.
- **Работа не встаёт.** Пока есть незавершённые задачи, координатор раз в 5 минут проверяет, можно ли их двигать. Когда работы не осталось, пульс выключается сам и чат не засоряется. Если координатор пытается остановиться при незавершённых задачах, хук возвращает его к работе.
- **Защита от потери контекста.** При переполнении контекст сжимается, и детали теряются. Поэтому координатор ведёт на диске файл состояния (задачи, решения, бюджеты, следующий шаг), а агенты — файлы своих заданий и прогресса. После сжатия хук возвращает правила и состояние в контекст, каждый пересказ сохраняется в архив, а у агентов есть постоянная память проекта.
- **Никто не работает вслепую.** Результат принимается только после проверки по факту:
  - интерфейсы и изображения — по скриншотам, которые агент открыл и описал;
  - видео — по кадрам и параметрам файла;
  - звук — по замерам громкости и открытой спектрограмме, а финальное прослушивание за вами;
  - код — по реальному запуску.

  Если проверить невозможно, задача помечается как непроверенная, а не как готовая.
- **Платное — только после изучения документации.** Прежде чем потратить деньги на генерацию (изображения, видео, голос и т. п.), агент обязан изучить официальную документацию конкретной модели и записать её в базу знаний проекта. Без свежей записи специальный хук блокирует платный вызов, а каждый разрешённый вызов пишется в журнал `.claude	eam\state\paid-calls.log`. Бесплатные действия (баланс, список моделей, оценка стоимости) не блокируются. Свои платные инструменты проекта можно добавить в `.claude	eam\paid-tools.local.json`.
- **Только профессиональные инструменты.** В продакшне запрещены инструменты, которые искажают видео, изображения, звук, интерфейс, тексты или код. Результат каждой обработки сравнивается с исходником.

Модель в таблице — значение по умолчанию. Под каждую задачу координатор выбирает модель и уровень усилий сам, по правилам из раздела 13 своего промта.

## Пересмотр моделей

Каждый день в 12:00 и 18:00 запланированная задача «Пересмотр моделей команды (Каркас)» сверяет раздел 13 промта координатора с актуальной линейкой моделей Claude. Если изменений нет, она ничего не трогает. Если изменения есть, она правит раздел, повышает версию и публикует её на GitHub, после чего все проекты получают уведомление об обновлении. Задача работает, пока открыто приложение Claude.
