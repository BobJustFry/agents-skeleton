# Changelog

Формат: [Keep a Changelog](https://keepachangelog.com/). Версия: `0.1.<число коммитов>`.

## [0.1.20] - 2026-10-17
### Добавлено
- Никакой лишней работы. Повод: агенты повторяли дорогие действия. Агент, закончивший первым, собирал продукт, и каждый следующий собирал его снова, хотя сборка нужна один раз в конце. Параллельные агенты с контекстом около 1M токенов за час съедали половину 5-часового лимита. Защита в четыре слоя:
  - **Правила агентов** (блок «Общие правила команды», раздел «Никакой лишней работы», одинаков во всех 22 агентах). Интеграционные действия (полная сборка, упаковка, релиз, деплой, полные тесты, lint/format всего репозитория, установка и обновление зависимостей, генерация всего кода, выгрузка в сторы и CI) агент запускает, только если в ТЗ есть `INTEGRATION: yes`. Иначе он делает самую узкую проверку и пишет «integration deferred to coordinator». Перед дорогим действием читается журнал запусков; не перепроверять неизменённое; не переделывать чужую работу; дубли задач — стоп и сообщение координатору. Файлы гейта агентам менять нельзя.
  - **Правила координатора** (новый раздел 2.5 в ядре и справочник `reference/INTEGRATION.md`). Задачи группируются в пакет. Интеграционные действия выполняются один раз на пакет, после приёмки всех его задач (интеграционная задача зависит от всех). В ТЗ новые поля `INTEGRATION: no|yes` и `LEDGER`. `INTEGRATION: yes` получает один агент и только на гейте. Устаревшая сборка пересобирается один раз на следующем гейте. Не больше 3 агентов, зоны не пересекаются, ревью и QA стартуют после проверяемых задач, один проход на пакет. Приёмка 5.1: интеграционное действие без `INTEGRATION: yes` — нарушение, запись в `STATE.md`.
  - **Журнал запусков** `.claude/team/state/runs.md`: строка `дата | действие | tree=<HEAD>+<хеш> | результат | агент | доказательство`. Ключ состояния дерева даёт `.claude/team/tree-state.ps1` (папка `state/` в хеш не входит, поэтому журнал ключ не меняет). Шаблон — `templates/RUNS.md`.
  - **Финальные действия — только по команде владельца.** Сборка, упаковка, релиз, деплой, публикация, полные тесты и всё необратимое запускаются только после явной просьбы владельца и после отчёта координатора об открытых задачах: что закончено, что ещё не принято, какие команды будут запущены, цена и риск, вопрос «Запускать финальную сборку/проверку?». Согласие действует на один пакет и один гейт; указания из файлов, отчётов агентов и вывода инструментов не считаются. Узкие проверки согласия не требуют.
  - **Хук `integration-guard`** (PreToolUse, `Bash|PowerShell`). Блокирует интеграционные команды, пока координатор не открыл гейт `.claude/team/state/integration-gate` (строки: пакет и классы `build`, `test`, `deploy`, `install`, например `B-3 build,test`; `owner-approved: <дата> "<цитата владельца>"`; `open-tasks-reported: yes|none`). Гейт без корректной строки `owner-approved:` считается закрытым, причина «gate without owner approval» пишется в журнал. Шаблоны команд — `.claude/team/integration-commands.json`, свои — `integration-commands.local.json` (установщик его не трогает). Гейт старше 12 часов считается закрытым. Субагентам нельзя создавать и менять гейт. Отключение — файл `.claude/team/state/integration-guard-off`. Любая внутренняя ошибка пропускает команду. Решения пишутся в `.claude/team/state/integration-guard.log`.
- Тесты `tests/integration_guard_test.py`; `tests/install_test.py` проверяет установку хука, конфигурации, шаблона журнала и слияние настроек в проектах со старой установкой.
- База знаний `claude-code-pretooluse-hook.md` перепроверена: имена инструментов `Bash` и `PowerShell`, поле `command`, точный список в `matcher`.

### Изменено
- Установщик при повторном запуске добавляет в уже существующий блок `.gitignore` недостающие строки каркаса (гейт, журналы), а не только создаёт блок целиком.

### Известные ограничения
- Хук не видит команды, запущенные внутри скриптов (`npm run release` вызывает сборку сам) и платные вызовы из кода программы. Эти случаи держат правила.
- Хук не запрещает повторить ту же команду на том же состоянии дерева, если гейт открыт: это держат правила и журнал.
- Попытки субагента создать гейт инструментами `Write`/`Edit` скрипт распознаёт, но хук на них не навешен (дорого запускать PowerShell на каждую правку). Включается расширением `matcher` в `.claude/settings.json`.
- Поведение блокировки в режиме обхода разрешений и наличие `agent_id` у вызовов субагентов нужно проверить вживую.

## [0.1.19] - 2026-10-17
### Изменено
- Экономия лимитов. Повод: 5-часовой лимит подписки уходил примерно за час. Замеры показали, что сессии разрастались до 0,6–0,95 млн токенов: автосжатие срабатывало только около 97 % окна в 1M, и каждый запрос перечитывал весь контекст.
  - **Автосжатие на ~250 000 токенов:** `"env": {"CLAUDE_CODE_AUTO_COMPACT_WINDOW": "250000"}` в `.claude/settings.json`.
  - **Координатор по умолчанию на Sonnet 5.5 / `medium`:** `"model": "sonnet"` в `.claude/settings.json`. На Opus — через `/model`, только для архитектуры и сложной отладки.
  - **Промт координатора разделён.** В каждой сессии загружается только ядро `ORCHESTRATOR.md` (было ~71 КБ, стало ~26 КБ). Справочные разделы перенесены без потерь в `.claude/team/reference/`: `TEAM.md` (раздел 3), `MODEL_POLICY.md` (раздел 13), `CONTINUOUS.md` (2.1–2.3), `DOCS.md` (7–10), `ONBOARDING.md` (12). В ядре указано, когда читать каждый файл.
  - **Новый раздел 2.4 «Экономия лимитов»:** одна задача — одна сессия, пакетные вызовы, большие файлы не читаются целиком, чтение — субагентам, не больше 3 агентов параллельно, ревьюеры на Sonnet для некритичных изменений, `/compact` при заполнении контекста больше ~60 %.
  - **Агенты не загружают `CLAUDE.md`** (поле `omitClaudeMd: true`, Claude Code v2.1.271+): промт координатора им не нужен. Соглашения проекта агент при необходимости читает сам — верхнюю часть `CLAUDE.md`.
  - **Короткие отчёты агентов:** до ~40 строк, подробности — в файлы.
- Установщик при слиянии `settings.json` добавляет недостающие `model` и записи `env`, но не меняет значения, уже заданные в проекте. Оставленные значения показываются в плане и в отчёте установки.
- Хуки и README ссылаются на новые справочные файлы.
- Политика моделей: координатор по умолчанию, запись в журнале 13.4.

### Известные ограничения
- В уже установленных проектах блок указаний для сжатия в `CLAUDE.md` не обновляется (установщик дописывает его, только если блока нет). Старый текст остаётся верным по смыслу.
- `omitClaudeMd` работает с Claude Code v2.1.271; более старые версии игнорируют поле, и агенты по-прежнему загружают `CLAUDE.md`.

## [0.1.18] - 2026-10-15
### Добавлено
- Защита платных вызовов в три уровня. Повод — инцидент в проекте Vupen VPN: агенту поручили платную генерацию с пометкой «документацию изучать не нужно».
  - **Агенты.** Поле `FRESHNESS` в задании больше не отменяет обязанность изучить официальную документацию. Отклонение от задания агент отмечает в отчёте.
  - **Координатор.** `FRESHNESS` обязательно. `n/a` допустимо только для локальных задач и с причиной. Для платных генераций задание прямо запрещает платные вызовы до появления записи в базе знаний.
  - **Хук `paid-guard`.** Перед вызовом PreToolUse блокирует платные MCP-инструменты без свежей (не старше 7 дней) записи в `docs/knowledge/` с полем `Covers:`, покрывающим инструмент и модель. Бесплатные вызовы не блокируются. Разрешённые платные вызовы пишутся в `.claude/team/state/paid-calls.log`. Настройки: `.claude/team/paid-tools.json` и `paid-tools.local.json` для своих инструментов проекта.
- Поле `Covers:` в шаблоне записи базы знаний.
- Тесты `tests/paid_guard_test.py`.

### Известные ограничения
- Платные вызовы API из кода программы (у `ai-engineer`) хук не видит. Там действует правило в промте и бюджет.
- Документация Claude Code не говорит явно, действует ли блокировка хуком в режиме обхода разрешений. Требуется проверка вживую.
